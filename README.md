## Две критичные находки

**P0-1. На закэшированных карточках товара `<title>`, `description`, `canonical` и `og:*` оказываются внутри `<body>`, а не в `<head>`.**

Next.js стримит метаданные браузерам и отдаёт их блокирующим образом ботам — это штатное поведение. Ломается оно на кэше nginx: ключ не учитывает User-Agent, `Vary` его тоже не содержит, поэтому на URL живёт один общий объект. Браузеров кратно больше, чем ботов, так что в кэш попадает стримовый вариант и дальше отдаётся всем.

```
Один URL, оба запроса — промах кэша:
  UA=Twitterbot   title на 2 725 байте    (</head> на 10 381)  ✅
  UA=Chrome       title на 118 623 байте  (</head> на 6 746)   ❌
```

Затрагивает 6 351 карточку — 97 % sitemap. Яндекс, Bing, VK, Telegram и WhatsApp получают именно испорченный вариант.

**P0-2. `?page=N` за пределом диапазона отдаёт 200, пустой список и `index, follow` с self-canonical.**

`?page=999`, `?page=99999`, `?page=1e9` — все 200 и все индексируемые. Параметр не закрыт в robots.txt, умножается на 35 категорий и 19 вариантов `?sub=`. Это генератор soft-404 неограниченного объёма.

## Проверка

Два независимых контура.

**Тесты логики** — без сети и без зависимостей, штатный раннер Node 22:

```bash
cd fixes && npm test        # 64 теста, 0 падений
```

Данные в тестах — с прода: те же названия товаров, те же значения `?page=`, тот же canonical.

**Регрессия против живого сайта:**

```bash
./tools/seo-check.sh
```

Каждая находка оформлена отдельным тестом. Прогон против продакшена 18.08.2026 — **4 PASS, 16 FAIL**; FAIL-ы соответствуют находкам аудита один к одному. По мере выкатки исправлений из `fixes/` они должны переходить в PASS.

```bash
BASE=https://staging.cosmex.ru ./tools/seo-check.sh   # против стейджа
```
