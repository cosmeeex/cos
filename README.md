# Честный знак × МойСклад — интеграция маркировки для Cosmex

Отдельный проект глубокой интеграции обязательной маркировки «Честный знак» с МойСклад для cosmex.ru. Цели: **не ошибаться и не получать штрафы**, легально продавать товар без кодов, довести процессы до состояния, когда менеджеры интуитивно понимают, что делать.

> Проект создан 19.08.2026 на базе четырёх исследований: нормативка ЧЗ на 2026 год, технический разбор API МойСклад, обзор существующих решений рынка и анализ реального ассортимента cosmex.ru (6 354 SKU). Всё — в `docs/`.

## Главные выводы исследования

1. **Cosmex — магазин ногтевого сервиса, а не парфюмерии.** Под маркировку косметики (ПП № 1681, волны 2025 г.) попадает **~41% ассортимента (~2 600 SKU)**, ядро — гель-лаки/базы/топы (ТН ВЭД 3304 30, обязательна для выпуска с 01.10.2025). Классической парфюмерии нет; в риск-зоне только 8 мистов NOIR «по мотивам» — нужны декларации (3303 или 3307?).
2. **Товар без маркировки продавать МОЖНО** — если он выпущен/ввезён до даты своей волны: без кодов до конца срока годности (обязательной домаркировки для косметики нет). Ключ — доказуемая дата выпуска. Товар выпуска после волны без кодов — нельзя: возврат поставщику, либо (для собственного импорта СТМ из Казахстана) маркируем сами как импортёр. Для желающих — полуавтоматический конвейер добровольной домаркировки (заказ КМ → печать → ввод в оборот).
3. **Горящие дедлайны:** с 01.07.2026 уже действуют обязательные ЭДО и вывод через кассу; **с 01.09.2026 — автоштрафы** по данным касс; 01.11.2026 — волна пинцетов/расчёсок/маникюрных наборов (это тоже ассортимент Cosmex!); 01.04.2027 — разрешительный режим для косметики.

## Что умеет проект

| Модуль | Команда | Что делает |
|---|---|---|
| **Аудит ассортимента** | `node src/cli.ts audit [--fix]` | классифицирует все товары МойСклад по 6 волнам маркировки, находит карточки без признака/ТН ВЭД/GTIN, `--fix` проставляет признаки |
| **Страж документов** | `node src/cli.ts serve` + `setup-webhooks` | по вебхукам проверяет каждую отгрузку/приёмку/продажу: нет кодов, кодов ≠ количеству, дубли, пересорт (чужой GTIN), битые сканы, русская раскладка сканера; светофор 🟢🟡🔴 + Telegram-алерты |
| **Сверка остатков** | `node src/cli.ts reconcile` | МойСклад ↔ ГИС МТ по GTIN: находит «висящие» коды, непринятые УПД, немаркированные остатки — с инструкцией по каждому расхождению |
| **Дистанционные продажи** | `node src/cli.ts distance` | контроль 3-дневного срока вывода из оборота по каждому интернет-заказу (pending → overdue → алерт) |
| **Конвейер домаркировки** | `node src/cli.ts plan-residuals [--create]` | план заказов КМ (лимиты 10 позиций/1000 кодов, цена 0,61 ₽/код, срок жизни 120 дней) и создание документов «Заказ КМ» в МойСклад |
| **Этикетки** | `node src/cli.ts labels файл [zpl\|tspl\|csv]` | печать DataMatrix напрямую на термопринтеры Zebra/TSC или CSV для BarTender |
| **Проверка скана** | `node src/cli.ts scan <код>` / `POST /scan` | валидация кода с рабочего места (структура GS1, контрольная цифра GTIN, починка сканов в русской раскладке) |

## Быстрый старт

Нужен Node.js ≥ 22.18. Зависимостей нет.

```bash
node --test 'tests/*.test.ts'      # 65 тестов, всё офлайн
cp .env.example .env               # заполнить MOYSKLAD_TOKEN (см. docs/access-checklist.md)
node src/cli.ts audit              # первый аудит ассортимента → reports/audit.md
node src/cli.ts serve              # панель: http://localhost:8787
```

По умолчанию `DRY_RUN=true`: никакие записывающие операции не выполняются, всё только в отчёты.

## Структура кода

```
src/
  core/        gs1.ts (разбор DataMatrix), config.ts, http.ts (ретраи, rate-limit)
  classifier/  rules.ts (6 волн, ТН ВЭД + ключевые слова), audit.ts
  moysklad/    client.ts (JSON API 1.2: товары, документы, trackingCodes, вебхуки,
               emissionorder, retireorder)
  crpt/        trueapi.ts, suz.ts, signer.ts (УКЭП через внешний подписант)
  guard/       checks.ts (правила стража), distance.ts (3-дневный срок)
  reconcile/   stocks.ts (сверка МС ↔ ЧЗ)
  residuals/   plan.ts (конвейер домаркировки), labels.ts (ZPL/TSPL/CSV)
  notify/      telegram.ts
  server.ts    вебхуки + панель · cli.ts — все команды
tests/         65 тестов на чистую логику (node:test, офлайн)
```

## Что дальше (после выдачи доступов)

1. Токен МойСклад → боевой `audit` по реальным 6 354 карточкам → починка карточек (`--fix` + ручной разбор особых случаев).
2. VPS + вебхуки → страж в бою, Telegram-алерты менеджерам.
3. Декларации на мисты NOIR + схема импорта СТМ → закрыть два главных риска ассортимента.
4. Еженедельная сверка (сначала по CSV из ЛК ЧЗ, после выдачи УКЭП — автоматически).
5. Фаза 2: виджеты в интерфейсе МойСклад (блокировка сохранения документов с ошибками прямо в UI) — см. architecture.md.
