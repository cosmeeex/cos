# Архитектура интеграции

## Общая схема

```
                    ┌──────────────────────────────────────────────┐
                    │                МойСклад (SaaS)               │
                    │  товары · приёмки · отгрузки · касса · ЭДО   │
                    │  документы маркировки (Заказ КМ, Вывод)      │
                    └───────┬───────────────────▲──────────────────┘
              вебхуки       │                   │  JSON API 1.2
   (demand/retaildemand/    │                   │  (чтение + создание
    supply/retireorder)     │                   │   документов)
                    ┌───────▼───────────────────┴──────────────────┐
                    │        ЭТОТ ПРОЕКТ (Node.js, zero-dep)       │
                    │                                              │
                    │  guard/    страж документов (светофор, блоки)│
                    │  classifier/ классификатор волн + аудит      │
                    │  reconcile/  сверка остатков МС ↔ ЧЗ         │
                    │  residuals/  конвейер домаркировки + этикетки│
                    │  guard/distance  3-дневный срок дист. продаж │
                    │  server.ts  вебхуки + панель менеджера       │
                    │  notify/    Telegram-алерты                  │
                    └───────┬───────────────────▲──────────────────┘
            True API (УКЭП) │                   │ СУЗ (OMS)
     cises/info·codes/check │                   │ заказ КМ (опц.)
                    ┌───────▼───────────────────┴──────────────────┐
                    │            «Честный знак» (ГИС МТ)           │
                    └──────────────────────────────────────────────┘
```

## Ключевые проектные решения

1. **Zero-dependency TypeScript на Node ≥22.18** (нативный strip-types). Нет npm-цепочки поставок, `npm test` работает без установки зависимостей. Вся бизнес-логика — чистые функции, покрытые тестами (65 шт.).

2. **МойСклад остаётся системой записи.** Мы не дублируем учёт: страж читает документы по вебхукам и валидирует, конвейер остатков СОЗДАЁТ документы «Заказ КМ»/«Вывод из оборота» через API, но кнопки отправки в СУЗ/ГИС МТ нажимает менеджер в UI МойСклад (API это не умеет — проверено по документации, см. moysklad-api.md §4). Так мы не строим второй ЛК ЧЗ и не берём на себя криптографию там, где она не нужна.

3. **Прямое подключение к True API — только для контроля** (сверка остатков, проверка статусов кодов). Подпись УКЭП вынесена во внешний подписант (`CRPT_SIGNER_CMD`, КриптоПро на той машине, где живёт сертификат) — интеграция не хранит ключи. До выдачи УКЭП сверка работает по CSV-выгрузке из ЛК ЧЗ.

4. **DRY_RUN по умолчанию.** Все записывающие команды в режиме «показать, что было бы». Продакшн включается осознанно (`DRY_RUN=false`).

5. **Ответ вебхуку — мгновенный 200**, обработка в очереди (лимит МойСклад 1500 мс). Rate-limiter консервативнее лимитов МС (40/3с, 4 параллельных).

## Потоки данных

| Поток | Триггер | Путь |
|---|---|---|
| Проверка документа | вебхук CREATE/UPDATE | МС → server → guard/checks → светофор + Telegram при 🔴 |
| Аудит ассортимента | cron/вручную | МС (все товары) → classifier → reports/audit.md (+ `--fix` проставляет trackingType) |
| Сверка остатков | еженедельно | МС stock/all + ЧЗ cises (INTRODUCED) → reconcile → reports/reconcile.md + Telegram |
| Дистанционные продажи | ежедневно | МС demand (14 дней) + retireorder → distance → алерты pending/overdue |
| Домаркировка | вручную по плану | classifier+stock → план → emissionorder (REMAINS/FOREIGN) в МС → менеджер: заказ/печать/ввод |
| Проверка скана | рабочее место | POST /scan → gs1 (структура, GTIN, раскладка) |

## Фазы развития

- **Фаза 1 (этот репозиторий):** аудит, страж, сверка, конвейер остатков, мониторинг сроков, SOP. Запускается на любом VPS.
- **Фаза 2 — виджеты в интерфейсе МойСклад** (Vendor API, приватное решение 1300 ₽/мес): светофор прямо в карточке Отгрузки/Приёмки с `validation-feedback` — физически блокирует сохранение документа с ошибками маркировки; подсказки SOP по месту. Требует регистрации кабинета разработчика МС.
- **Фаза 3 — к дедлайнам 2027:** офлайн-контур разрешительного режима (01.04.2027), поэкземплярный учёт УПД (01.07.2028), волна личной гигиены (01.11.2026: регистрация группы, домаркировка пинцетов/расчёсок до 31.10.2027).

## Ограничения (честно)

- Ввод в оборот, перемаркировка, списание КМ, агрегация в МойСклад доступны только через UI — эти шаги остаются за менеджером (интеграция готовит документы и напоминает).
- Сверка по «объёмно-сортовому» принципу (GTIN × количество). Поэкземплярная сверка (какие именно серийники) — после подключения True API с УКЭП.
- Признак «розничности» отгрузки для монитора дистанционных продаж сейчас эвристический (наличие КМ в отгрузке); после подключения к реальной базе уточним по типу контрагента/каналу.
