# Патчи по находкам аудита

Рабочий код, готовый к переносу в проект. Каждый модуль закрывает конкретную находку из [`../docs/seo-audit.md`](../docs/seo-audit.md) и снабжён ссылкой на неё в шапке файла.

> Исходников приложения в репозитории нет — на момент работы он был пуст. Поэтому здесь не «предложения», а собранные и покрытые тестами модули: чистая логика проверена на реальных данных с прода, компоненты и страницы написаны под Next.js App Router и переносятся как есть.

## Тесты

```bash
cd fixes && npm test
```

64 теста, без внешних зависимостей — штатный раннер Node 22. Тестовые данные взяты из замера прода 18.08.2026: те же названия товаров, те же значения `?page=`, тот же canonical.

## Порядок применения

1. **`nginx/cosmex-cache.conf`** — снимает потолок индексации 6 351 карточки. Всё остальное без этого работает вхолостую.
2. **`src/lib/seo/pagination.ts`** + `src/app/catalog-page-example.tsx` — закрывает бесконечное краулинговое пространство.
3. `src/components/*` + `src/app/brand/page.tsx` — возвращает вес внутренних ссылок.
4. Остальное — по очереди из [`../docs/growth-plan.md`](../docs/growth-plan.md).

После каждого шага: `../tools/seo-check.sh` — соответствующие проверки должны переходить из FAIL в PASS.

## Что нужно поправить руками

Эти правки не в коде, а в контенте и настройках:

- **`llms.txt`**, строка про Prozatochka: ссылка ведёт на `/catalog?brand=Prozatochka`, закрытый в robots.txt. Заменить на `/brand/prozatochka` (отдаёт 200).
- **Значения в `product-jsonld.ts`** — `DEFAULT_SHIPPING` и `DEFAULT_RETURNS` собраны из `/page/delivery` и `llms.txt`. Сверьте с офертой: разметка, расходящаяся с реальными условиями, — повод для ручных санкций.
- **`aggregateRating`** подключать только после того, как на карточке появятся настоящие отзывы, видимые пользователю.
- **`getBrandsWithLandings()`** в `src/app/brand/page.tsx` — заглушка на статическом словаре. Подключить к тому же источнику, что питает `/brand/[slug]`.

## Про импорты

Модули импортируют друг друга с явным расширением `.ts` — это позволяет запускать тесты штатным раннером Node без сборки и без единой внешней зависимости. Next.js такие импорты понимает; нужен флаг `allowImportingTsExtensions` (см. `tsconfig.snippet.json`). Если в проекте принят другой стиль — уберите расширения в `src/` и запускайте тесты через `tsx`.
