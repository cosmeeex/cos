# P0-1, вариант Б: убрать стриминг метаданных на стороне приложения

Основной фикс — на nginx (`fixes/nginx/cosmex-cache.conf`): он разводит кэш на ботовый и пользовательский варианты и сохраняет быстрый TTFB живым пользователям. **Этот файл — запасной вариант**, если правки кэша недоступны или нужно закрыть проблему прямо сейчас.

## Суть

Next.js стримит метаданные браузерам и отдаёт их блокирующим образом только ботам из `htmlLimitedBots`. Если отключить стриминг, вариант становится один — и вопрос кэш-ключа отпадает сам собой.

```ts
// next.config.ts
const nextConfig = {
  experimental: {
    // Метаданные всегда блокирующие: <title>, description, canonical и og:*
    // гарантированно оказываются в <head> независимо от User-Agent.
    // Плата — TTFB карточки товара ждёт разрешения generateMetadata.
    streamingMetadata: false,
  },
}
```

> Ключ находится в `experimental` и между минорными версиями Next переезжал. Сверьтесь с документацией **своей** версии перед выкаткой и убедитесь, что сборка не пишет предупреждение о неизвестной опции — иначе настройка молча не применится.

## Цена решения

TTFB карточки товара сейчас 1,29 с без кэша. Блокирующие метаданные добавят к этому время `generateMetadata` (запрос товара в МойСклад) для **каждого** пользователя, а не только для ботов.

Частично это компенсирует CDN: `s-maxage=300` означает, что медленный рендер отрабатывает один раз на 5 минут, а остальные запросы идут из кэша. Но на промахе кэша пользователь ждёт дольше.

Поэтому: если правка nginx возможна — делайте вариант А. Вариант Б хорош как временная мера.

## Третий вариант, если ни один не подходит

Расширить `htmlLimitedBots`, чтобы ботов надёжно ловило приложение, — но **это не решает проблему**, пока кэш-ключ не учитывает User-Agent: ботовый ответ всё равно перезатрётся пользовательским. Само по себе расширение списка бесполезно; оно имеет смысл только вместе с правкой ключа кэша.
