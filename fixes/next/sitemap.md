# P2-9 / прочее по sitemap.xml

Текущее состояние: 6 524 URL, 1,54 МБ, дублей нет, лимиты Google (50 000 URL / 50 МБ) не нарушены. Базово всё в порядке — ниже точечные правки.

## 1. `/catalog/aktsii` отсутствует

Страница отдаёт 200 и упомянута в `llms.txt` как «реальные скидки из товарного учёта», то есть закрывает коммерческие запросы («акции», «скидки», «распродажа»). В sitemap её нет.

Заодно на ней нет `BreadcrumbList` и `ItemList` — в отличие от остальных категорий, где обе схемы присутствуют.

## 2. Нет `<image:image>`

Ни одного тега изображения при 6 351 карточке с фотографиями. Для бьюти-товаров поиск по картинкам — реальный канал: оттенок гель-лака ищут визуально.

```ts
// app/sitemap.ts
{
  url: productUrl,
  lastModified: product.updatedAt,
  images: [proxiedImageUrl(product.images[0], 1200)],   // Next сам развернёт в <image:image>
}
```

## 3. `changefreq` и `priority` можно убрать

Проставлены на всех 6 524 URL. Google игнорирует оба поля с 2015 года, Яндекс — тоже. На объём это ~15 % веса файла без какого-либо эффекта.

## 4. 103 URL без `<lastmod>`

`<lastmod>` учитывается обоими поисковиками при планировании обхода. Проставить везде — либо дату реального изменения, либо дату публикации.

Распределение по датам сейчас здоровое (основная масса — 2026-05 … 2026-08), то есть поле в целом живое, пробел точечный.

## 5. Разделить на индекс

При 6 524 URL это ещё не обязательно, но с ростом каталога удобнее:

```
/sitemap.xml            → sitemapindex
  /sitemap-pages.xml    (статика, категории, бренды, города, заточка)
  /sitemap-products.xml (товары)
  /sitemap-blog.xml     (статьи)
```

Даёт раздельную статистику индексации по типам страниц в Вебмастере и Search Console — сразу видно, какой раздел проседает.

## 6. Товары не в наличии — более старый `lastmod`

~32 % карточек в статусе `OutOfStock` (см. `docs/growth-plan.md`, п. 6). Отдавать им честный старый `lastmod`, чтобы краулинговый бюджет уходил на живые позиции.
